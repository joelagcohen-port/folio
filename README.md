# Folio

**Folio is an AI-assisted household finance workspace.** Its conversational assistant, Ask Folio, helps people make sense of household account activity, spending, budgets, recurring items, goals, and cash-flow plans—alongside a dashboard for reviewing the underlying financial picture.

The assistant is designed to ground answers in household data returned by Folio's server-side finance tools. It can explain spending and budget progress, search transactions, discuss recurring activity and upcoming cash flow, and help shape financial plans. It distinguishes recorded activity from projections and is designed to surface stale, incomplete, or unavailable evidence rather than treat it as a complete picture.

## AI-assisted workflows

- **Ask Folio:** a streaming conversational interface with bounded, authenticated access to financial reads and a saved conversation.
- **Analysis and planning:** tool-backed views of spending, budget progress, transactions, recurring items, goals, and cash-flow scenarios.
- **Contextual coaching:** AI-written explanations of supplied financial facts and tradeoffs, with spending arithmetic and forecasts kept in deterministic finance code rather than generated by the model.
- **Reviews and follow-through:** optional scheduled, read-only instructions and bounded watches or commitments for selected finance questions.
- **Human-reviewed changes:** the assistant can prepare supported proposals for review and confirmation. Separately configured automatic-action policies can authorize narrowly eligible tasks, subject to safety controls.

These workflows depend on compatible backend services and configuration. This portfolio snapshot contains no seeded financial records and does not imply that any hosted service is running.

## How the AI layer is structured

1. The assistant UI streams a user turn to a server route, which calls the OpenAI Responses API with a defined set of finance tools rather than giving the model direct database access.
2. The server validates tool names and arguments, forwards authenticated operations to the finance backend, and returns bounded results for the assistant to use as evidence.
3. Assistant-prepared changes use review/confirmation flows; separately configured automatic-action policies can authorize eligible tasks. Scheduled assistant instructions use a separate runner with read-only financial tools and bounded execution limits.
4. Assistant conversation, watches, task state, and finance operations depend on backend functions and data structures that are not fully included in this export.

Relevant code includes `app/ask-folio-panel.tsx`, `app/api/ask-folio/route.ts`, `app/folio-assistant-contract.ts`, `app/folio-assistant-task-runner.ts`, `app/folio-agent-actions.ts`, `app/api/folio-coaching/route.ts`, and `app/folio-server.ts`. The web app also provides account activity, budgets, cash-flow views, savings and debt goals, planning scenarios, and rental reporting.

## Architecture

- `app/` contains the React dashboard, API routes, assistant workflows, and client-side finance features. `public/dashboard.html` and `public/folio*` provide additional interactive dashboard assets.
- `components/`, `hooks/`, and `lib/` contain reusable UI, calculations, and shared server helpers.
- `backend/supabase/functions/` contains selected, isolated Supabase Edge Function source closures. See `backend/edge-functions.json` for the source inventory and `backend/README.md` for its limits.
- The web build uses React, TypeScript, Vite/Vinext, and the Cloudflare Vite plugin. Edge Function source targets the Deno/Supabase runtime.

## Run the web app locally

Requirements: Node.js 22.13 or newer and pnpm.

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

Create a production web bundle with `pnpm build`. The local auth shim is loopback-only and intended for UI development; it is not production authentication. Production hosting must provide a trusted auth adapter that validates users and sets the server-side identity expected by the API routes.

## Backend and configuration

The backend export is a curated source snapshot, not a turnkey deployment or fresh-project bootstrap. It includes six read-only current app-facing function snapshots, a read-only Plaid webhook snapshot, and five reviewed source-candidate closures. Candidate source is not a deployment-status claim. See [`backend/README.md`](backend/README.md) for details.

Database schema, migrations, rows, RLS policies, and Supabase deployment configuration are intentionally omitted. Functions depend on compatible tables, views, RPCs, and service settings, so a new Supabase project will not run from this repository alone. Independently review schema, permissions, JWT settings, and secrets before deploying any function.

`.env.example` contains names with empty values and safe non-secret defaults. Keep credentials in ignored local env files or a deployment secret manager; never use `NEXT_PUBLIC_` or `VITE_` prefixes for private values. Optional flows may require OpenAI, Plaid, and market-data-provider accounts. Push delivery requires `FOLIO_PUBLIC_URL`, validated as HTTPS except for HTTP loopback development. Server-side calendar calculations default to UTC; browser dates use the browser's configured time zone.
